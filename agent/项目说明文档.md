## 一、项目概述

### 1.1 项目简介

Agent 智能体管理平台是一个基于 **Spring Boot 3.2.5** + **LangChain4j** 构建的 AI 智能体管理系统，提供智能体（Agent）的创建与管理、知识库（RAG）文档管理、工具（Tools）管理、AI 对话、用户权限管理、操作日志审计等完整功能。平台集成了大语言模型（LLM）能力，支持流式和非流式两种对话模式，具备会话记忆和知识库检索增强生成（RAG）能力。

## 二、模块详细说明

### 2.1 配置管理（Setup）

管理 AI 服务商的配置信息，包括 API 密钥、模型地址等。每个 Agent 可关联一个配置。

**安全特性：**

-   API 密钥使用 **AES-128-ECB** 加密存储，数据库仅存密文
-   查询时自动解密返回前端明文
-   新增/修改时自动加密后存入数据库

### 2.2 智能体管理（Agent）

管理 AI 智能体实例，支持创建、编辑、删除、启用/禁用等操作。

**关联关系：**

-   一对一关联配置（Setup）
-   多对多关联知识库（Knowledge），通过 `agent_knowledge` 中间表
-   前端请求时 `knowledgeIds` 使用 JSON 数组格式，如 `[1, 2, 3]`

**智能体类型：**

-   `chat`：对话型智能体
-   `task`：任务型智能体
-   `workflow`：工作流型智能体

### 2.3 知识库管理（Knowledge）

基于 RAG（检索增强生成）技术，管理知识库文档。

**功能特性：**

-   支持文档上传、下载、删除
-   文档自动分割（分段大小 500 字符，重叠 100 字符）
-   向量嵌入存储（PersistentEmbeddingStore，文件持久化，重启后无需重新向量化）
-   检索相似度阈值 0.5，最大返回 3 条结果
-   文件存储于 `data/knowledgebase/` 目录
-   支持源文件路径记录（sourceFilePath）

**知识库类型：**

-   `document`：文档型
-   `qa`：问答型
-   `web`：网页型

### 2.4 工具管理（Tools）

管理 AI 可调用的工具/函数。

**工具类型：**

-   `api`：API 接口工具
-   `function`：函数工具
-   `builtin`：内置工具

**功能特性：**

-   工具代码以文件形式存储于 `data/tools/` 目录
-   支持参数说明（parameterDescriptions，JSON 格式）
-   支持参数配置（parameters，JSON 格式）
-   支持接口地址（endpoint）配置

### 2.5 AI 对话服务

集成 LangChain4j，提供智能对话能力。

**对话模式：**

-   **流式对话（SSE）**：`POST /api/ai/chat/stream`，以 Server-Sent Events 方式逐 token 返回
-   **非流式对话**：`POST /api/ai/chat`，一次性返回完整回复（含 sessionId）
-   **GET 流式对话**：`GET /api/ai/chat`，兼容旧版调用（不持久化，仅使用 memoryId）

**核心能力：**

-   会话记忆（Redis + ChatMemoryStore），默认保留 20 条消息，TTL 2 小时（与 JWT 一致）
-   知识库检索（RAG），自动检索相关文档
-   系统业务工具调用（SystemBusinessTool），可查询 Agent、Tools、Knowledge、Setup 数据
-   对话历史持久化（MySQL），以会话级存储
-   会话历史查询（分页，按更新时间倒序）
-   会话历史删除（POST /api/ai/history/delete，统一 ids 集合，传几个删几个）
-   会话记忆清除（DELETE /api/ai/memory/clear，同时清除 Redis 记忆和 MySQL 历史）

### 2.6 用户管理（User）

管理平台用户，支持三级权限体系和用户头像。

**用户字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| username | String | 用户名（2~20 字符，全局唯一） |
| password | String | 登录密码 |
| avatar | String | 头像 URL（可选） |
| admin | Integer | 管理员等级 |
| status | Integer | 状态：1-正常，0-禁用 |

**权限等级：**

| 等级 | 标识 | 说明 |
|------|------|------|
| 超级管理员 | 2 | 不可删除，拥有所有权限 |
| 管理员 | 1 | 可管理普通用户 |
| 普通用户 | 0 | 基础权限 |

**默认账号：** `admin` / `123456`（超级管理员）

**头像上传功能：**

-   接口路径：`POST /api/upload/avatar`
-   请求方式：`multipart/form-data`
-   文件校验：仅支持图片格式（jpeg/png/gif/webp/bmp），最大 2MB
-   存储目录：`static/uploads/avatars/`
-   文件名格式：`avatar_yyyyMMdd_HHmmss_随机后缀.扩展名`
-   返回完整的头像访问 URL
-   前端流程：上传头像 → 获取 URL → 通过 `PUT /api/system/user/profile` 更新到数据库

### 2.7 登录管理（Login）

-   验证码登录（图片验证码，5 分钟有效期，Redis 存储）
-   测试验证码接口（GET /api/login/captcha/test，返回验证码明文，仅用于调试）
-   JWT Token 认证，有效期 2 小时
-   Token 双重校验（JWT 解析 + Redis 验证）
-   登录日志记录（成功/失败、IP 地址）

### 2.8 日志审计

-   **操作日志（OperationLog）**：记录用户操作行为，含模块、操作类型、描述、IP
-   **登录日志（LoginLog）**：记录用户登录历史，含状态、IP、时间
-   **删除功能**：支持按 ID 集合删除（统一接口，传几个删几个）和删除全部，均为逻辑删除（MyBatis-Plus @TableLogic）

### 2.9 数据看板（Data）

提供系统仪表盘数据统计，聚合展示核心业务指标。

**接口列表：**

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 仪表盘概览 | GET | `/api/data/overview` | 聚合所有统计指标 |
| Token 趋势 | GET | `/api/data/token-trend` | Token 用量趋势数据 |
| Agent 排行 | GET | `/api/data/agent-usage` | Agent 按 Token 用量排名 |
| 类型分布 | GET | `/api/data/agent-distribution` | Agent 按类型分组统计 |

**统计指标：**

-   `totalTokens`：所有 Agent 的 Token 用量总和
-   `activeAgentCount`：已启用的智能体数量
-   `totalAgentCount`：智能体总数量
-   `knowledgeCount`：知识库数量
-   `toolCount`：工具数量
-   `tokenTrend`：Token 用量趋势（当前日期 + 总量）
-   `agentUsage`：Agent 用量排行（按 tokens 降序）
-   `agentDistribution`：Agent 类型分布（按 type 分组）

## 四、数据库设计

### 4.1 核心业务表

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `setup` | 配置管理表 | name, api_key, base_url, status |
| `agent` | 智能体表 | name, description, type, setup_id, tokens |
| `knowledge` | 知识库表 | name, description, type, document_count, content_path, source_file_path |
| `tools` | 工具表 | name, description, type, code_path, parameter_descriptions, endpoint, parameters |
| `agent_knowledge` | 智能体-知识库关联表 | agent_id, knowledge_id |
| `knowledge_tool` | 知识库-工具关联表（预留） | knowledge_id, tool_id |

### 4.2 系统表

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `user` | 用户表 | username, password, avatar, admin, status |
| `login_log` | 登录日志表 | user_id, username, ip, status, login_time |
| `operation_log` | 操作日志表 | user_id, username, module, action, description, ip |
| `chat_history` | 对话历史表 | user_id, session_id, title, messages(JSON), message_count |

### 4.3 通用字段设计

所有业务表均包含以下通用字段：

-   `id`：主键，BIGINT 自增
-   `status`：状态，1-正常/0-禁用
-   `is_deleted`：逻辑删除，0-未删除/1-已删除
-   `create_time`：创建时间，DATETIME
-   `update_time`：更新时间，DATETIME（自动更新）

## 五、安全设计

### 5.1 认证流程

```
用户登录 → 验证码校验 → 密码验证 → 生成JWT → 存入Redis → 返回Token
     ↓
后续请求 → CustomFilter拦截 → JWT解析 → Redis校验 → 存入ThreadLocal
```

### 5.2 数据安全

-   **API 密钥加密**：AES-128-ECB 加密存储，数据库仅存密文
-   **密码安全**：目前为明文存储（后续可升级为 BCrypt）
-   **Token 安全**：JWT + Redis 双重校验，支持主动失效
-   **逻辑删除**：所有业务表使用逻辑删除，数据可追溯

### 5.3 接口鉴权

-   除 `/api/login/**` 外，所有接口均需 JWT 认证
-   排除路径通过 `agent.jwt.exclude-paths` 配置
-   超级管理员（admin=2）不可被删除
